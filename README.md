# Satience - CDCL SAT Solver in Go

[![Go Version](https://img.shields.io/badge/go-1.22+-blue.svg)](https://golang.org)
[![License](https://img.shields.io/badge/license-MIT-green.svg)](LICENSE)

> **AI-Built Project**: Satience was designed and implemented entirely by an AI assistant. From the core CDCL algorithm to watched-literal propagation, conflict analysis, and all optimizations — every line of code was generated by AI.

**Satience** is a sound and complete CDCL (Conflict-Driven Clause Learning) SAT solver written in Go. It implements modern SAT solving techniques including 1-UIP conflict analysis with BIG-based clause minimization, watched-literal propagation, VSIDS/CHB variable selection with a lazy activity heap, adaptive structure-aware preprocessing (SCC equivalence detection, bounded variable elimination, subsumption), and inprocessing (vivification, learned-clause subsumption).

## Features

### Core CDCL Engine
- **1-UIP Conflict Analysis**: Learns asserting clauses with the UIP at position 0 and a backjump-level literal at position 1 (MiniSat invariant). Includes the resolved-variable non-re-addition fix and level-0 literal skip.
- **Clause Minimization**: Recursive minimization (skips level-0 literals in reason clauses) combined with BIG-based (Binary Implication Graph) minimization — a literal is removable iff BFS from it through binary clauses reaches another literal genuinely in the clause.
- **Backjumping**: Single-pass backjump-level computation; after backjump, `qhead` skips re-processing the earlier trail and the asserting literal is propagated explicitly.
- **Watched Literals**: 8-byte `Watch` structs (`ClauseIdx int32` + `Blit uint32`) with bit-packed clause index (learned flag, watch position, clause id) and a cached blocking-literal index for fast-path skip via direct array indexing.
- **Restarts**: Luby sequence (base 200) plus Glucose-style EMA-smoothed LBD restart (fires when LBD > ratio × avg, default ratio 10.0, min 10 conflicts) and a level-capped restart for long-clause instances (anti-thrashing gated).
- **Phase Saving**: Occurrence-count-initialized polarity, updated on every decision and propagation.
- **Clause Database**: Dynamic learned-clause limit (~15% of original clauses, min `max(300, numVars×10)`, max 100K) with LBD-based, usage-aware deletion (least-propagated clauses deleted first within each LBD tier). High-LBD shrink adaptively reduces the floor on consistently high-LBD workloads. Tombstone deletion with periodic level-0 compaction (23× GC reduction).

### Variable Selection Heuristics
- **VSIDS** (default): Variable State Independent Decaying Sum with a lazy activity heap. O(1) decay via the MiniSat `varInc` trick (decay factor 0.95, MiniSat-equivalent). Lazy heap: assigned variables sink to −∞ and are sifted back up on unassign — the heap never empties, eliminating O(n) rebuilds.
- **CHB** (optional, `-chb`): Conflict History Based heuristic.
- **LBD-based Activity Bonus**: Adaptive scale `max(10, 200000 × binaryRatio / numVars)` — small binary-heavy instances get a larger bonus, large/long-clause instances get the minimum.

### Preprocessing (Adaptive, Structure-Aware)
Runs an iterative simplification loop (subsumption → BVE → unit propagation) where each pass creates opportunities for the others:
- **Tautology + Duplicate-Literal Removal** (all instances): O(total literals) with a temporary seen-array.
- **Pure Literal Elimination** (all instances): Assigns single-polarity variables and removes satisfied clauses.
- **Structure Classifier**: Scores instances by `binaryRatio`, `ternaryRatio`, and `longClauseRatio`. Structured instances (score ≥ 0.7) enable unit propagation; random instances (score < 0.7) skip it (it causes 76× more conflicts there).
- **SCC-Based Equivalence Detection**: Tarjan's SCC on the binary implication graph. Literals in the same SCC are merged into a representative; `l`/`¬l` in the same SCC → UNSAT. Merge-significance gate skips substitution on small merges while still detecting contradictions.
- **Bounded Variable Elimination** (standard Davis-Putnam VE): Resolves all `(x∨A)×(¬x∨B)` pairs, reconstructs eliminated variables by trying `x=true` then `x=false`. O(1) amortized selection via a bucket queue. Budget-limited (default 5M resolvents; 2M for large instances).
- **Forward Subsumption + Self-Subsumption (Strengthening)**: On the original clause database during preprocessing.

### Inprocessing (at level-0 restart boundaries)
- **Vivification**: Clause shortening via assisted-assignment replay. Deterministic budget (`maxCheckPerRound=2000` clauses) with a conflict-gap gate (fires only after ≥20K new conflicts). Updates LBD to `min(oldLBD, newSize)` after shrinking.
- **Learned-Clause Subsumption**: Forward subsumption + self-subsumption strengthening on the learned clause DB, using binary learned clauses as the subsumers. Self-gating via early-return when no binary learned clauses exist (free on random instances). LBD updated to `min(oldLBD, newSize)` on strengthening.
- **Learned-Clause Compaction**: Reclaims tombstoned entries (deletions) when tombstones exceed ~33% of capacity, rebuilding only learned-clause watches.

## Usage

### Basic Usage

```bash
# Solve a CNF file (single positional argument; flags must precede it)
./satience instance.cnf

# Print satisfying assignment
./satience -model instance.cnf

# Print and verify the model against all clauses
./satience -verify instance.cnf

# Show solving statistics
./satience -verbose instance.cnf
```

### Output Format

Satience uses the SAT Competition 2026 output format:

```
c Comment lines start with 'c'
s SATISFIABLE
v 1 -2 3 -4 5 0
```

**Exit Codes:**
- `10`: SATISFIABLE
- `20`: UNSATISFIABLE
- `0`: UNKNOWN (timeout or resource limit reached)

### Notable Flags

| Flag | Default | Description |
|---|---|---|
| `-model` | off | Print satisfying assignment |
| `-verify` | off | Verify model (implies `-model`) |
| `-verbose` | off | Show solving statistics |
| `-no-preprocess` | off | Disable adaptive preprocessing |
| `-chb` | off | Use CHB heuristic instead of VSIDS |
| `-max-iter N` | 0 | Maximum iterations (0 = unlimited) |
| `-seed N` | 0 | Random seed for deterministic solving |
| `-restart-base N` | 200 | Luby restart sequence base multiplier |
| `-restart-glucose-ratio R` | 10.0 | Glucose restart when LBD > ratio × avg |
| `-vivify-period N` | 50 | Run vivification every Nth restart (0 = disabled) |
| `-lbd-scale R` | 0 | LBD bonus scale (0 = adaptive) |
| `-cpuprofile file` | — | Write CPU profile to file |

## Architecture

### Data Structures
- **Literal**: `uint32` (bit 31 = sign, bits 0–30 = variable index). Variables 0-based internally, 1-based in DIMACS.
- **Watch**: 8 bytes — `ClauseIdx int32` (bit 31 = learned, bit 30 = watch position, bits 0–29 = clause id) + `Blit uint32` (cached `litTrue` index for fast-path skip).
- **Implication encoding**: `≥0` original clause; `≤-5` learned (`-learnedIdx-5`); `-1` decision; `-2` unit-prop preprocess; `-3` pure-literal; `-4` reserved. The 4-slot offset separates learned-clause decode from preprocessing sentinels.
- **Learned clauses**: Contiguous literal pool with packed `LearnedClauseLoc` (`Offset int32` + `Size int32`). Deletion uses tombstones (`Size=0`); a `learnedAlive []byte` bitmap provides a 1-byte hot-path tombstone check.

### Key Algorithms
1. **Conflict Analysis**: 1-UIP with recursive + BIG-based clause minimization.
2. **Backjumping**: Single-pass backjump-level computation; UIP placed at position 0.
3. **Restart Policy**: Luby (base 200) + Glucose-style EMA LBD (ratio 10.0) + level-capped restart for long-clause instances.
4. **Clause Database**: Dynamic LBD-based, usage-aware deletion; tombstone + periodic compaction.
5. **Propagation**: Watched literals with bit-packed clause index decode and cached `learnedMetadata`.
6. **Variable Selection**: VSIDS (default) or CHB, with a lazy activity heap and O(1) decay.
7. **Preprocessing**: Iterative subsumption → BVE → unit propagation loop, preceded by tautology/duplicate removal, PLE, and SCC equivalence detection.

## Design Constraints

Satience is single-threaded by design:
- **Single-threaded only** — no parallel search.
- **No incremental solving** — no assumption stack or incremental interface.
- **No proof generation** — no UNSAT core or resolution proof output.
- **DIMACS format only** — no native cardinality constraint propagators.
